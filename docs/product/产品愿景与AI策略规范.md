# 此间 - 产品愿景与 AI 策略规范

> [!IMPORTANT]
> 本文档定义了“此间”（NCU Book）作为南昌大学 Mobile-First 校园 AI 知识产品的核心定位、移动端信息架构、AI 运行边界、防幻觉策略及 Citation 引用证据链契约。所有后续功能迭代均必须符合本规范。

---

## 1. 产品愿景与核心边界

### 1.1 一句话定义
此间是面向南昌大学学生的 **Mobile-First 校园知识产品**：学生可以直接提问、检索文档或浏览板块，并得到带有站内权威依据、可追溯的校园信息。

### 1.2 核心判断
- **服务主体**：首要服务学校为南昌大学；内容模型允许未来扩展学校，但第一阶段不实现多学校复杂切换逻辑。
- **AI 定位**：AI 是知识库的检索与解释层，**不需要人格化聊天体验**。
- **入口策略**：针对不知道能问什么的新生提供场景探索入口；对已有明确问题的学生提供直接提问框。
- **功能互补**：关键词搜索、文章阅读和 AI 问答是互补入口，不能互相取代。
- **长文保护**：保留原作者的观点、上下文和阅读节奏，不得将其强行拆为营销卡片。

### 1.3 成功标准
1. 学生能在手机上以最少步骤提出明确问题。
2. 学生能从 AI 回答无缝跳到站内的具体文档章节和来源。
3. 学生能用关键词找到对应文章或段落，而不会被生成式回答干扰。
4. 内容维护者只在 Notion 中日常编辑；公开站独立呈现内容，不依赖 Notion 访问权限。

> [!CAUTION]
> **非目标 (Non-Goals)**：
> - 不做人格化陪聊、论坛或社交社区。
> - 不把 AI 伪装成官方部门或自动发布敏感政策内容。
> - 不追求“全校最全”而牺牲来源、时效和可维护性。
> - 不以传统目录作为首页主入口，也不以一堆视觉卡片替代文档正文。

## 2. 移动优先的信息架构 (IA)

```text

│  ├── 最新公告卡片 (更新说明 + 新生必看入口)               │
```

- **首页**：首屏以宋体人文大标题「校园里的事，在此问明白。」与经典名言「是什么曾经拯救过你，就用它来更好地拯救这个世界」为视觉重心。核心交互由胶囊提问搜索框驱动，下方紧承公告卡片与 6 大板块（共 31 篇）极简双列目录。
- **板块与文档页**：文章页保持单列、连续、专注的沉浸阅读体验（严禁常驻双侧栏）。移动端顶部提供：返回上一级（`←`）、居中板块进度与大标题、当前板块目录抽屉（`☰`）、关键词搜索（`Q`）。正文支持 Notion 语义化红蓝提示框、表格、黄页电话一键呼叫/复制。
- **关键词搜索**：独立全屏搜索视图，不与 AI 问答混合。仅返回文档标题、所属板块和命中的段落摘录，关键词在摘录中高亮标出（`<mark class="search-highlight">`），点击跳到对应文章锚点，不生成总结或答案。
- **AI 问答**：首页可直接发起提问；文档页右下提供 50px 纯圆形固定吉祥物悬浮球（`right: 18px; bottom: 22px;` 物理脱离正文滚动流），打开时默认携带当前页面及所在章节为优先上下文，点击出处角标（`¹`）可平滑滚动至原文并触发 1.6s 墨蓝柔光呼吸高亮（Flash Highlight）。

## 3. 生产 AI 运行策略与安全约定

### 3.1 Provider 与模型边界
- **服务端通信**：使用服务端 OpenAI-Compatible HTTPS 接口，具体供应商通过环境变量切换。客户端不得包含 Endpoint、API key 或模型 ID。
- **模型配置**：聊天模型（生产推荐 `deepseek-v4-flash`）和 Embedding 模型必须显式配置，禁止代码内静默替换。
- **结构化输出**：模型只返回结构化 `claims`、`sourceIds` 和 `confidence`，不得生成页面标题、URL、锚点或内容版本。
- **回答模式**：`AI_ANSWER_MODE` 支持 `fixture`（本地模拟测试）、`shadow`（静默验证）、`production`（生产上线）。

### 3.2 预算、可靠性与日志 Retention

| 维度 | 指标参数 / 策略规则 | 备注说明 |
|---|---|---|
| **请求超时** | 8000 ms (8 秒) | 超时自动切至降级提示 |
| **重试策略** | 仅对 429、502、503、504 重试 1 次 | 避免无限轮询 |
| **单次检索上限** | 最多检索 8 个原文块 | 输入总字符 ≤ 12,000 |
| **模型输出上限** | 700 tokens | 保持回答简明遏制长篇大论 |
| **服务端 P95 延迟** | ≤ 5000 ms (5 秒) | 超过即报警或降级 |
| **IP 限流频次** | 每 IP 每分钟 10 次 | 仅记录不可逆哈希 |
| **日志保留周期** | 运行日志 14 天 / 反馈关联数据 30 天 | 严禁记录完整用户提问与 Key |

### 3.3 来源、防幻觉与敏感控制
- **知识库隔离**：检索限定 `school=ncu` 和当前发布指针；旧版本、失败版本及外校内容禁止进入 Prompt。
- **确定性校验**：模型引用的每个 Source ID 必须来自本次检索。未知 ID、无来源事实或版本不一致由确定性校验器删除或降级。
- **敏感领域限制**：招生截止时间、费用、资格、成绩/处分、医疗与安全属于敏感信息。缺少权威来源时不输出事实结论，只提示核对官方渠道；紧急安全/医疗问题提供非诊断性的求助方向。
- **分歧处理**：来源冲突必须保留分歧并标记 `needs-verification`，不得由模型擅自择一。

## 4. AI 回答与 Citation 证据链契约

> [!TIP]
> **事实性回答最低标准**：每一个事实性结论必须至少关联一条可用 Citation；Citation 仅可引用已发布内容版本。无可用 Citation 时，AI 不得给出事实性结论，必须说明资料不足。

### 4.1 TypeScript 数据类型契约
```ts
type Citation = {
  id: string;
  pageId: string;
  pageTitle: string;
  anchor: string;             // 对应正文 b-<sourceBlockId>
  contentVersion: string;
  excerpt: string;
  sourceUrl?: string;
};

type AnswerClaim = {
  id: string;
  text: string;
  citationIds: string[];
  status: "grounded" | "needs-verification" | "insufficient";
};

type AnswerSession = {
  id: string;
  question: string;
  pageContext?: { pageId: string; anchor?: string };
  citations: Citation[];
  claims: AnswerClaim[];
  confidence: "grounded" | "partial" | "insufficient";
};
```

### 4.2 展示与跳转行为
- **引用匹配**：每一个事实性结论对应一个 `AnswerClaim`；其 `citationIds` 必须引用 `citations` 中至少一个有效 ID。
- **UI 显示**：UI 必须把每个 Claim 的引用显示在该 Claim 附近；Citation 显示页面标题与段落摘录，并可跳转到具体段落锚点。
- **置信度状态**：
  - `grounded`：所有事实性 Claims 都有可用 Citation；
  - `partial`：明确分隔已证实 Claims 和待核实 Claims；
  - `insufficient`：不输出事实性 Claims。
- **跳回上下文**：从回答跳转到来源页时，URL 或客户端状态必须携带 `answerSession`；返回操作恢复同一回答、滚动位置和输入草稿。
