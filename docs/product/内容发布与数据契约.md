# 此间 - 内容发布与数据契约

> [!IMPORTANT]
> 本文档定义了“此间”（NCU Book）在 Notion 内容源同步、格式解析、编辑约定、网页嵌入白名单、资源镜像策略以及 Supabase 存储发布时的完整技术规范与数据 Schema 契约。

---

## 1. 内容发布架构与规则

Notion 是内容编辑源；公开站是独立、可访问、可检索的发布端。同步目标是保留内容的结构与语义。

```text
Notion 页面树与富块 (Editor Source)
        │
        ▼  (publish-notion.ts 同步器)
站内 Page / Block-Tree / Asset / Anchor 数据
        │
        ▼  (ArticleRenderer 富内容渲染)
公开文章页  ├─► 关键词索引
            └─► AI 检索切片 (b-<blockId>)
```

### 1.1 必须保留的内容语义
- 页面树、标题层级、段落、列表、引用、强调色和链接。
- 表格、图片、图片组、分栏（Columns）、文件和外部嵌入。
- Notion 内部页面链接，在发布后转换为站内路由。
- 页面、标题和可引用段落的稳定锚点（`b-<blockId>`）。
- 来源、更新时间、适用校区和风险级别等可供 AI 使用的元数据。

### 1.2 发布端约束与安全白名单
- **资源托管**：图片和附件必须下载镜像上传至 Supabase 站内 Bucket (`published-content`)，严禁直接暴露出 Notion 临时签名 URL。
- **外部嵌入白名单 (Allowlist)**：网页嵌入不是可同步资源。第一版仅允许 `https://school-map.ncuos.com/`，其余网页嵌入统一降级为标题、原链接和“在外部页面打开”的外链块。
- **自适应排版**：多栏（Columns）在宽屏并列、手机端自然纵向堆叠；表格在手机端支持横向滚动并固定表头。提示块（Callout）仅保留提示语义，克制为阅读注释样式，禁止卡片化正文。
- **失败容错**：未知块、资源下载失败、内部链接无目标或数据校验失败时，该页面本次发布失败。单页失败继续提供该页最近一次成功版本；首次发布失败的页面不进入导航、搜索或 AI 索引。
- **第三方与飞书集成扩展**：支持通过 `/api/sync/lark` 进行飞书多维表格 (Bitable) 信息的定时同步与批量 Upsert，并提供与学生反馈入口绑定的飞书问卷 (Lark Form) 存根拓展。

## 2. Notion 页面树写作与编辑约定

### 2.1 页面树与 slug 规则
- 同步器只读取 `NOTION_ROOT_PAGE_ID` 指定的根页面及其后代。
- 根页面的直接子页面发布为站内板块首页；更深层子页面发布为文档页面树。
- Notion 页面 UUID 是 `Page.id`，父页面 UUID 是 `Page.parentId`。标题或位置变化不得改变身份 UUID。
- `slug` 首次发布时生成并持久化，后续修改标题或移动位置不得改变网址。

### 2.2 支持的内容块映射表

| Notion 内容 | 站内发布块 (Publish Block) | 渲染与处理规则 |
|---|---|---|
| 普通正文、引用 | `paragraph`、`quote` | 保留粗体/斜体/下划线/删除线/代码与链接 |
| 一级至三级标题 | `heading` | 生成 `b-<Notion block UUID>` 稳定锚点 |
| 无序、有序及嵌套列表 | `bulleted-list`、`numbered-list` | 保持列表层级与嵌套关系 |
| 提示块 (Callout) | `callout` | 按内容风险映射为 `info`、`warning` 或 `risk` 样式；支持子块递归 |
| 分隔线 | `divider` | 正文中的低干扰水平分隔线 |
| 表格 | `table` | 保持行列格式，手机支持横滚 |
| 图片、文件 | `image`、`file` | 镜像上传站内 Bucket，保存校验和 `Asset.publicUrl` |
| 分栏 | `columns` | 手机端按从左到右顺序纵向堆叠 |
| 子页面、页面提及 | `page-link` | 自动解析为站内内部路由 |
| 校园地图嵌入 | `embed(provider="school-map")` | 渲染 `school-map` 允许插件 |
| 书签、普通外链 | 外链标记 | 保留原 URL 与题注 |

### 2.3 资源限制与元数据配置
- **资源文件上限**：单个资源上限 50 MiB；ZIP、旧版 Word 与 OOXML 办公附件保留正文显示名，并使用 ASCII 安全存储键镜像。
- **大图处理**：大图在阅读器中延迟加载并异步解码，避免阻塞文章首屏。
- **页面元数据**：`school` 第一阶段固定为 `ncu`；`sourceUrls`、`campus`、`audiences`、`topics` 与 `riskLevel` 由同步配置按页面 ID 覆盖；未配置时默认使用 `riskLevel="normal"`。

## 3. 完整 TypeScript 数据与 Schema v2 契约

> [!NOTE]
> 代码库对应 Schema 文件位于 [`lib/content/schema.ts`](../../lib/content/schema.ts)，Supabase 生产数据库模式定义位于 [`supabase/schema.sql`](../../supabase/schema.sql)，类型契约位于 [`lib/database.types.ts`](../../lib/database.types.ts)。
>
> **Schema v2 架构核心原则**：
> 1. **渲染端按页窄查询**：`published_pages` 物化 `route_path`（如 `/docs/campus-shuttle`）与 `tree_path` JSON，文档阅读页按单页 slug 窄查询，不再全量拉取全库；
> 2. **分块暂存 + 短事务原子切线**：发布长流程调用 `stage_published_chunk` 分块暂存，完成后通过 4 参 `commit_published_content_version` 瞬时切线；
> 3. **任务调度与版本分家**：独立 `sync_jobs` / `sync_job_logs` 记录任务进度与日志，`content_versions` 保持纯版本语义；
> 4. **SQL 全文检索单一事实源**：`published_search_segments` 采用 `tsvector`（简单分词全文检索）与 `pg_trgm`（三元组模糊匹配），替代 Node 内存线性扫描。

```ts
export type RiskLevel = "normal" | "needs-verification" | "sensitive";
export type ClaimStatus = "grounded" | "needs-verification" | "insufficient";

export type RichTextSpan = {
  plainText: string;
  href?: string;
  pageId?: string;
  annotations: {
    bold?: boolean;
    italic?: boolean;
    strikethrough?: boolean;
    underline?: boolean;
    code?: boolean;
    color?: string;
  };
};

export type Block =
  | { type: "paragraph"; id: string; anchor: string; richText: RichTextSpan[] }
  | { type: "heading"; id: string; anchor: string; level: 1 | 2 | 3; richText: RichTextSpan[] }
  | { type: "bulleted-list" | "numbered-list"; id: string; anchor: string; items: Array<{ id: string; richText: RichTextSpan[]; children: Block[] }> }
  | { type: "quote"; id: string; anchor: string; richText: RichTextSpan[]; children: Block[] }
  | { type: "callout"; id: string; anchor: string; tone: "info" | "warning" | "risk"; icon?: string; richText: RichTextSpan[]; children: Block[] }
  | { type: "divider"; id: string; anchor: string }
  | { type: "table"; id: string; anchor: string; hasHeaderRow: boolean; rows: Array<{ id: string; cells: RichTextSpan[][] }> }
  | { type: "image"; id: string; anchor: string; assetId: string; caption?: RichTextSpan[] }
  | { type: "file"; id: string; anchor: string; assetId: string; name: string; caption?: RichTextSpan[] }
  | { type: "columns"; id: string; anchor: string; columns: Array<{ id: string; blocks: Block[] }> }
  | { type: "embed"; id: string; anchor: string; provider: "school-map"; canonicalUrl: string; title: string }
  | { type: "page-link"; id: string; anchor: string; pageId: string; richText: RichTextSpan[] };

export type Page = {
  id: string;
  schemaVersion: 1;
  contentVersion: string;
  parentId: string | null;
  title: string;
  slug: string;
  status: "published" | "failed";
  lastEditedTime: string;
  lastPublishedAt: string;
  metadata: {
    school: "ncu";
    campus?: string[];
    audiences?: string[];
    topics?: string[];
    sourceUrls: string[];
    riskLevel: RiskLevel;
  };
};

export type Asset = {
  id: string;
  sourceBlockId: string;
  contentVersion: string;
  kind: "image" | "file";
  publicUrl: string;
  checksum: string;
  alt?: string;
};

export type SearchIndexEntry = {
  id: string;
  schemaVersion: 1;
  contentVersion: string;
  pageId: string;
  pageTitle: string;
  sectionPath: string[];
  anchor: string;
  plainText: string;
  blockType: "paragraph" | "heading" | "quote" | "callout" | "table" | "page-link";
  updatedAt: string;
};
```

## 4. 数据库表与核心 RPC 契约

### 4.1 核心数据表结构 (Schema v2)

- `content_versions`：内容版本控制主表（状态：`pending` \| `staging` \| `published` \| `failed`）；
- `published_pages`：发布页面表（包含 `route_path`, `tree_path`, `school`, `risk_level`, `source_urls`）；
- `published_blocks`：正文富文本块树表（稳定 `b-<sourceBlockId>` 锚点）；
- `published_assets`：托管静态资源文件表（图片与附件）；
- `published_search_segments`：全文检索段表（包含 `search_vector` 生成列与 `plain_text gin_trgm_ops` 索引）；
- `published_content_pointer`：全局唯一指向单行表（Singleton `singleton = true`）；
- `sync_jobs` / `sync_job_logs`：独立同步任务调度与流式执行日志表；
- `evaluation_runs` / `evaluation_cases`：AI 质量评测运行记录与用例集表；
- `rate_limit_buckets`：IP 分钟级原子计数限流桶表。

### 4.2 核心 RPC 存储过程

| 函数名 | 权限与安全 | 功能说明 |
|---|---|---|
| `stage_published_chunk(p_content_version, p_pages, p_blocks, p_assets, p_segments)` | `service_role` | 分块暂存内容，支持多批次写入，每次写入 ≤ 300KB |
| `commit_published_content_version(p_content_version, p_expected_current_version, p_checksum, p_summary)` | `service_role` | 4 参短事务原子切线，锁指针并完成上线 |
| `rollback_published_content_version(p_target_version, p_expected_current_version)` | `service_role` | 将线上指针原子回退到已发布历史版本 |
| `search_published_segments(p_query, p_limit)` | `anon, authenticated, service_role` | 结合 `ts_rank_cd` 与 `similarity` 进行站内关键词全文检索 |
| `match_published_segments(p_question, p_limit)` | `service_role` | AI 问答粗召回，返回候选段落及其原始相关度得分 |
| `consume_ask_rate_limit(p_bucket_key, p_minute_window)` | `service_role` | 原子分钟级 IP 限流计数 |

---

## 5. 校验与发布更新触发

只有当完整版本通过交叉链接、资源、搜索锚点与 Schema 校验后，才通过 4 参短事务存储过程 `commit_published_content_version` 触发更新 Supabase 中的 `published_content_pointer`，使学生端通过 Next.js ISR Tag 机制获得增量物理刷新（`revalidateTag("published-content-pointer")`）。
