# Next.js 应用与路由架构设计说明 (app/)

本文档全面阐述「此间 (NCU Book)」Next.js 15 App Router 生产应用的页面架构、渲染策略、路由清单、API 端点契约、状态流转与运维规范。

---

## 1. 核心架构设计原则

仓库根目录是唯一的学生端 Next.js 生产应用，采用 **SSG (静态生成) + ISR (增量增量再生) + 极速 Node.js API Routes** 混合架构，在确保首屏毫秒级加载的同时，提供强大的实时问答与搜索能力。

```text
学生客户端 (Mobile-First 360px~430px)
       │
       ├──► 静态页面访问 (SSG + ISR 极速直出)
       │      ├─ / (首页: 搜索框 + 5大场景卡 + 指南推荐)
       │      ├─ /docs/[slug] (文档阅读器: 正文优先 + 物化 Block 树)
       │      └─ /sections/[slug] (板块聚合页: 目录树清单)
       │
       └──► 动态交互请求 (Node.js API Routes)
              ├─ POST /api/ask (AI 溯源问答 + 分布式滑动窗口限流)
              ├─ GET  /api/search (全文关键词即时分词检索)
              └─ POST /api/admin/* (运维管理: Notion 发版/切线/评测)
```

1. **移动端优先 (Mobile-First)**：以 360px、390px、430px 屏幕为基准设计与验证布局，再自适应平板与桌面，确保单手操作丝滑；
2. **正文优先原则**：阅读器以正文为主体，严禁常驻双侧栏挤占移动端阅读面积，板块树通过轻量抽屉（Drawer）按需滑出；
3. **流程隔离原则**：关键词搜索（`/search` & `/api/search`）仅返回匹配文档段落；AI 问答（`/api/ask`）由学生主动发起并在独立弹层展示，两者流程与结果互不混淆；
4. **秒级全网缓存刷新**：发版或切线回滚成功后，通过 `revalidateTag('published-content-pointer')` 与 `revalidatePath('/', 'layout')` 瞬间全网失效 CDN 与静态页面缓存。

## 2. 页面路由清单字典 (Page Routes)

| 路由路径 | 渲染模式 | 核心职责 | 关键设计与技术实现 |
| :--- | :--- | :--- | :--- |
| **`/`** | SSG + ISR | **首页门户** | 集成全局搜索与问答入口、五大新生高频场景导航卡（网络、选课、出行、设施、办事）、推荐指南与核心板块列表。 |
| **`/docs/[slug]`** | SSG + ISR | **文档详情阅读器** | 基于物化富文本块（Block Tree）进行高保真渲染，支持锚点跳转、来源溯源与右下角带页面上下文的 AI 问答浮窗。 |
| **`/sections/[slug]`** | SSG + ISR | **板块聚合页** | 聚合指定板块下的所有文章目录树与分类阅读导航。 |
| **`/search`** | 动态服务端渲染 | **关键词搜索页** | 接收 `?q=...` 参数，直连 Supabase FTS 检索，毫秒级展现匹配文章、段落文字片段与高亮关键词。 |
| **`/admin`** | 动态（Session 守卫） | **管理控制台** | 组织内容发布、版本时间线（回滚/彻底删除）、AI 质量评测看板与问答测试沙盒四大面板。 |
| **`/admin/login`** | 静态渲染 | **后台登录页** | 提供管理员口令校验界面，验证通过后签发加密 HTTP-Only 会话 Cookie。 |

## 3. API 路由端点字典 (API Endpoints)

所有 API 路由均运行在 Node.js 运行时（`export const runtime = "nodejs"`），划分为学生端公开接口与管理端鉴权接口：

### 3.1 学生端公开接口

| 端点路径 | 请求方法 | 鉴权要求 | 核心职责与技术实现 |
| :--- | :--- | :--- | :--- |
| **`/api/ask`** | `POST` | 公开（限流） | **AI 校园问答**。内置基于 IP SHA-256 哈希的分钟级滑动窗口限流；从 Supabase 粗召回候选段落，调用大模型生成答案，经 Grounding 事实校验与 Citation 归因后返回结构化观点。 |
| **`/api/search`** | `GET` | 公开 | **全文搜索**。调用 Supabase `search_published_segments` RPC，基于 `tsvector` + `pg_trgm` 进行分词与模糊匹配，返回段落摘要与锚点。 |

### 3.2 管理端运维接口（严格鉴权）

| 端点路径 | 请求方法 | 鉴权要求 | 核心职责与技术实现 |
| :--- | :--- | :--- | :--- |
| **`/api/admin/auth`** | `POST` | 管理员口令 | **管理员登录与登出**。签发或注销有效期 7 天的 `cijian_admin_session` 安全 Cookie。 |
| **`/api/admin/publish-notion`** | `POST` / `GET` | Session / Token | **发布总调度**。支持 `publish`（发版/预检）、`rollback`（切线回滚）、`delete`（彻底双清删除）。集成 Next.js `after()` 异步后台调度与实时进度轮询。 |
| **`/api/admin/evals/run`** | `POST` | Session / Token | **AI 质量评测执行**。支持在线模式与离线 Mock 基准模式，返回 6 大指标评分。 |
| **`/api/admin/evals/cases`** | `GET` | Session / Token | **评测用例列表**。拉取数据库当前激活的 36 题评测基准。 |
| **`/api/admin/ask/inspect`** | `POST` | Session / Token | **白盒探针分析**。透视单次提问的召回得分、Prompt 上下文注入、Token 消耗与观点归因树。 |

```text
┌────────────────────────────────────────────────────────────────────────┐

├──────────────────┬──────────────────┬──────────────────────────────────┤

├──────────────────┼──────────────────┼──────────────────────────────────┤
│ 1. 极致首屏秒开  │ SSG + ISR 静态化 │ 移动端弱网环境下首屏 <200ms 呈现 │
│ 2. 沉浸文档阅读  │ 物化 Block 树渲染│ 排版清晰克制，段落锚点精准高亮   │
│ 3. 关键词即时查  │ SQL GIN 索引检索 │ 毫秒级返回匹配文章与具体段落片段 │

└──────────────────┴──────────────────┴──────────────────────────────────┘
```

## 5. 全局样式与排版规范

1. **全局令牌统一管理**：全局样式集中在 [`app/globals.css`](file:///c:/chengxu/ncubook/app/globals.css) 中定义设计令牌（Tokens）变量与排版重置；
2. **严禁页面私有补丁**：禁止在 `globals.css` 中编写针对特定页面的临时布局样式；
3. **触控与无障碍规范**：所有可点击控件最小尺寸不小于 **44px**（`.tap-target`），键盘导航与焦点指示器统一为 `.focus-ring`。
